# Paper 8 — Synthetic Digital Twin for Manufacturing Monitoring and Batch-Release Readiness

**Working title:** *Circular by Construction: What Synthetic Batch-Record
Generators Can and Cannot Establish for Pharmaceutical Release Decisions*

## What this paper is

Not a release-readiness system. A benchmark, an evaluation protocol, and a
measured argument that the way synthetic digital twins of batch manufacturing are
currently validated does not support the claims made with them.

The workbook scoped this as *"can a synthetic digital twin detect abnormal process
trajectories and predict release readiness?"* on *"synthetic GMP-style data based
on published process ranges"*. As scoped, that design is circular: the twin would
be trained on simulator output and scored against simulator output, so every
number would describe the simulator rather than any real process. The paper takes
that circularity as its subject instead of its method.

## The three-axis evaluation, and what could actually be assessed

| Axis | Status |
|---|---|
| **Fidelity** — do synthetic records match real batch distributions, on marginals *and* joints | Assessed against **SECOM**, a real manufacturing corpus. **Not** assessable against real *pharmaceutical* batch records — none are public. |
| **Utility** — does a model trained on synthetic transfer to real | Assessed: train-on-synthetic / test-on-real against SECOM's real held-out test set, versus a train-real baseline. |
| **Privacy** — does the generator memorise its source records | Fully assessed: DCR ratio, NNDR, exact-copy fraction, distance-based membership inference. This is the axis where the results are unambiguously valid. |

The headline experiment is none of those individually: it is running the *same*
protocol on the simulated corpus and on the real corpus and measuring whether the
conclusions agree.

## Data

| Corpus | What it is | Role |
|---|---|---|
| `data/raw/secom/` | UCI SECOM: 1,567 real semiconductor production runs, 590 signals, real pass/fail disposition | The real anchor. Real process data with a real disposition label. |
| `data/raw/openfda_enforcement/` | the openFDA drug enforcement export dated 2026-08-27, copied from `Papers/_shared/`: 17,899 records in the export, of which 17,898 are drug records classified by the rule set | Anchors the simulator's failure-mode mix to real failures. Cannot anchor trajectories. |
| `data/interim/sim_*` | 2,000 simulated batches, generated by `src/02_simulator.py` | The simulated corpus. Regenerable from the recorded seed; nothing to download. |

**IndPenSim is not present.** It was planned as a third corpus (pharma-relevant
batch structure) but the download was not completed. Its absence is stated in the
paper's Limitations rather than papered over.

## Running it

Scripts run in order from `src/`. Each writes JSON to `results/`; nothing is
computed twice and no number is typed by hand.

```
python 01_profile_real_data.py   # profile SECOM + build the recall failure prior
python 02_simulator.py           # generate the simulated corpus
python 03_evaluate.py            # fidelity/utility/privacy on both corpora, 10 seeds  (~1 h)
python 04_monitoring.py          # multiway-PCA monitoring + release readiness
python 05_figures.py             # all figures -> figures/*.pdf
python 06_tables.py              # numbers.tex + table_*.tex
python 07_agreement_ci.py        # per-seed correlations + the axis contrast
python 08_verify_manuscript.py   # re-check the manuscript against results/
latexmk -pdf paper.tex
```

Requires numpy, scipy, pandas, scikit-learn, matplotlib, torch (CPU is fine).

## Every number is traceable

`numbers.tex` and `table_*.tex` are generated by `src/06_tables.py` from the JSON
in `results/`. The paper body contains no hand-typed results. All stochastic
results are reported as mean ± sd over the same ten seeds; there are no
single-run numbers in the paper.
